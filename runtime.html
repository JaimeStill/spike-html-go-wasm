Runtime

Go built for GOOS=js run in this page through the spike's runtime: one worker, started on the first Run, holding each scenario's compiled module, its output streamed as written. Nothing loads until a Run. The spike's question and evidence.

hello

A program: its main prints one line to standard output and exits.

probe

A handler scenario: one long-lived instance serving handlers through the bridge. format indents the input as JSON or answers its parse error; files writes, lists, reads back, and removes files under a temporary directory in the in-memory filesystem; spin loops without yielding until Stop; crash panics outside any handler, naming the input, and the Go runtime prints the panic to standard error and exits with code 2.

Stop terminates the worker, ending whatever runs, and hands the compiled module to a fresh one: the next Run starts a new instance without fetching or compiling again. A Run while another is pending stops that one first, which rejects with stopped.
