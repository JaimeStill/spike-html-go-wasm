Playground

Edit the Go below and Run it: Go's own compiler and linker, built for GOOS=js, compile and link your files here in the page, then your program's main runs, its output and exit in the console and each phase's time beside it. The first Run fetches the toolchain and the standard library's packages your imports need; later Runs fetch only the packages a new import adds. The spike's question and evidence. 

// Command hello is the spike's first program built for GOOS=js GOARCH=wasm: it imports only the
// standard library and prints one line. It is a program scenario: the components page's Go demo
// runs its main to completion in the runtime's worker, which reports the line as stdout output
// and the exit code 0. It stays the standard-library baseline.
package main

import (
	"fmt"
	"runtime"
)

func main() {
	fmt.Printf("hello from Go %s on %s/%s\n", runtime.Version(), runtime.GOOS, runtime.GOARCH)
}

What a program holds

Every .go file is compiled as one package main, importing the standard library alone, as GOOS=js GOARCH=wasm builds it: no go.mod, local subpackages, cgo, assembly, or go:embed, and no arguments or standard input. Every other file sits in the program's working directory, so os.ReadFile("input.txt") reads a file named input.txt; each Run starts from those files again, and nothing a run writes outlives it.

Ctrl or Cmd+Enter runs from inside the demo; Stop ends a build or a run, and the next Run keeps the compiled toolchain. Your files live only in this page: a reload starts from hello again.
